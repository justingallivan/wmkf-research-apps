## Design Specificity Verdict

**LLM assessment:** The product truth is specific; the page architecture is not. The honorarium explains when the value is stamped, campaign defaults explain request overlays, and Final Writeup audiences model actual Grant Programs. But `pages/admin.js:2968-3065` renders 24 peer-level sections in a single sequence. The composition is a generic admin component append log; WMKF specificity lives inside the panels instead of in the page's organization.

Live inspection found a 6,063px default-state page, 24 top-level sections, a 15-link global navigation wrapping to three desktop rows, and a default-open Final Writeup editor interrupting the transition from operational monitoring to general configuration.

**Deterministic scan:** `detect.mjs --json pages/admin.js` returned 9 advisory `design-system-font-size` findings: 7 uses of 10px and 2 uses of 11px at `pages/admin.js:507,511,527,1053,1312,2013,2018,2022,2821`. When Model Configuration was expanded, two repeated 10px class sites produced 126 rendered micro-labels. The findings are accurate against `DESIGN.md`; compact badges are context-sensitive, but this repetition makes the issue real rather than incidental.

**Visual overlays:** No reliable user-visible overlay was available. Browser inspection succeeded in a fresh local tab, but the browser exposed no mutable injection API, so the Impeccable overlay server was not started and no overlay is claimed.

## Overall Impression

The individual editors are unusually thoughtful about consequential changes, but the page asks administrators to supply the missing information architecture themselves. The largest opportunity is to replace the vertical inventory with an attention-first overview and five goal-based workspaces. Consolidate navigation and context while preserving each editor's independent save contract.

## What's Working

1. **Consequential copy is excellent.** Editors explain consumers, timing, defaults, and future-only effects rather than merely exposing storage fields.
2. **Critical safety behavior is visible.** Final Writeup audiences use revision-aware replacement and stale-reference handling; Review Questions preserve edits across conflicts; App Access reloads canonical state after partial failure.
3. **The visual language fits the product.** Neutral surfaces, restrained semantic color, and explicit labels match the Clear Workbench direction.

## Cognitive Load

Seven of eight checks fail: single focus, chunking, grouping, visual hierarchy, one thing at a time, minimal choices, and working-memory demand. Progressive disclosure is the one pass because `CollapsibleCard` lazy-mounts on first open. Administrators still face 24 top-level choices and must mentally connect campaign dates, honorarium, attachments, policies, questions, email copy, and reviewer-search runtime.

## Consolidation Map

The recommended primary navigation is five items: **Overview, Operations, Workflows, AI, People & Access**.

It is a dashboard, not another configuration panel. |
| **Operations** | Service Health; Health Check History; System Alerts; Operational Events; Maintenance Jobs; Secret Expiration; Alert Recipients; Dynamics Explorer Feedback | Health (Current/History), Incidents (Alerts/Event Log/Notification Routing), Jobs & Retention, Credentials, Feedback & Quality. Preserve alert and event record semantics. |
| **Workflows** | Site Visit Recipients; Final Writeup Matrix Audiences; Reviewer Campaign Timeline; Honorarium; Reviewer Search Time Budget; Release Attachments; Policies; Review Questions; Email Defaults | External Review, Final Writeups, Site Visits, Grantee Communications, Shared Governance. Show setting scope badges: Global, Per Grant Program, or Request Override. |
| **AI** | API Usage; Model Configuration; Prompt Templates; Executor budgets currently embedded in Prompt Templates | Overview, Models, Prompts, Execution Budgets. Workflow screens deep-link to filtered AI settings instead of duplicating editors. |

`Quick Links` should stop being a top-level section. Put the Vercel link in Operations, Anthropic in AI, and the credentials runbook in Credentials. Dynamics Explorer Feedback should either live under Operations → Feedback & Quality or move to an app-owned quality surface if it remains app-specific.

### External Review consolidation

The External Review overview should answer: **What configuration will govern the next reviewer campaign?** It should show the effective cycle dates and quota, honorarium, portal-only/attachment behavior, review-question count/version, active reviewer-policy versions, reviewer email-template readiness, and search runtime/model health. Secondary views then edit each domain.

Final Writeup audiences should not be merged into External Review simply because both use the word “reviewer.” Final Writeup is a program-specific internal matrix with complete revisioned audience replacement; external review governs invitations, honoraria, release, policies, and external submissions.

Policies remain a canonical Governance library because the visible allowlist contains reviewer COI, reviewer AI-use, and grantee waiver slots. External Review and Grantee Communications should deep-link into filtered policy views rather than create duplicate policy editors. Email Defaults likewise remains one canonical per-key store, presented through workflow filters.

## Contract-Safe Boundaries

### Findings

1. **READY WITH NAMED CHANGES — Goal-based navigation is compatible with current contracts.** The recommendation moves existing editors into task workspaces; it does not require merging persistence or APIs.
2. **NEEDS REWORK — Any cross-editor “Save all” is unsafe.** App Access can partially complete a prefix before failure; Review Questions saves a full ordered set atomically with optimistic concurrency; policies and prompts publish immutable versions; Final Writeup replaces a revisioned whole configuration; email defaults save one key at a time.
3. **READY WITH NAMED CHANGES — Route/tab moves must preserve editor lifetime.** Current accordions lazy-mount once and then remain mounted. Tabs that unmount editors could discard draft state and deactivate navigation guards unless the shell explicitly preserves or blocks the transition.

### New Issues

- **P1 — Unified save would hide partial success and audit semantics.** Required change: keep per-editor save controls and outcomes; use overview readiness indicators only for navigation, never as a second write contract.
- **P1 — Moving Final Writeup can break existing deep links.** Required change: preserve `#final-writeup-matrix-audiences` or add an explicit redirect to the new canonical route/view.
- **P1 — Multiple filtered views can create duplicate editable truth.** Required change: one canonical mounted editor per setting family; other workspaces use deep links or read-only status summaries.

### Final Verdict

**READY WITH NAMED CHANGES** for IA planning. Preserve independent saves, deep links, lazy-load behavior, editor draft lifetime, unsaved-change guards, and canonical ownership of each setting. The exact “recent changes” and readiness-summary data contract needs a separate probe before implementation.

## Priority Issues

### P1 — No goal-based information architecture

**Why it matters:** Administrators must scan or remember 24 sibling sections whose order reflects feature addition, not user intent.

**Fix:** Add an attention-first Overview and persistent local navigation for the five workspaces above. Complex editors become secondary views rather than another accordion.

**Suggested command:** `$impeccable shape`

### P1 — External-review administration is fragmented

**Why it matters:** Preparing a campaign requires reconstructing related state from timeline, honorarium, release, policies, questions, email defaults, and search runtime.

**Fix:** Create one External Review overview with effective values and readiness links while preserving each editor's save boundary.

**Suggested command:** `$impeccable shape`

### P1 — Keyboard and screen-reader tasks have blocking gaps

**Why it matters:** Service cards and health-history rows are click-only; accordions omit `aria-expanded`/`aria-controls`; Review Questions is drag-only for reorder; App Access checkboxes do not announce the user/app intersection.

**Fix:** Use semantic disclosures, keyboard reorder controls, explicit checkbox labels, focus handling, and announced async status.

**Suggested command:** `$impeccable audit`

### P1 — Operational monitoring is not attention-first

**Why it matters:** Health, history, alerts, events, jobs, credentials, and usage errors are separate large panels, so administrators must correlate incidents manually.

**Fix:** Build an Operations Overview around exceptions, freshness, ownership, and investigation links; put healthy history and routine details behind secondary views.

**Suggested command:** `$impeccable distill`

### P2 — Visual consistency does not express hierarchy or consequence

**Why it matters:** Static and interactive cards share hover treatment; actions alternate among ink, blue, indigo, and text links; 10px model metadata repeats 126 times when expanded.

**Fix:** Standardize action hierarchy, reserve elevation for interaction, add domain-level structure, and bring repeated metadata to the documented type floor.

**Suggested command:** `$impeccable polish`

## Persona Red Flags

**Alex — power user:** Investigating an error requires traversing Health, History, Alerts, Events, and Usage separately. Updating a campaign then requires distant editors with independent save states. Browser Find is effectively the page's primary accelerator.

**Sam — keyboard/screen-reader user:** Click-only service cards and table rows block detail inspection. Accordion state is not programmatically exposed, app-access checkboxes lack user/app names, and question reordering is drag-only.

**Morgan — WMKF program-operations superuser:** Configuring the next external-review cycle means checking seven dispersed areas with no readiness summary. Excellent local copy cannot confirm that the overall campaign is ready.

## Minor Observations

- The page subtitle omits most of the actual surface: workflows, policies, recipients, access, and feedback.
- “Reviewer” currently means external reviewer, reviewer discovery, and internal Final Writeup reviewer; labels should qualify which.
- Final Writeup is default-open despite being a periodic, specialized workflow.
- Static cards inherit hover elevation and imply clickability.
- Each accordion exposes two controls for the same toggle.
- Quick Links appears only after the entire page, far from the task context it is meant to support.

## Questions to Consider

- Is Admin one destination, or are system operator, program administrator, AI administrator, and access administrator distinct workspaces sharing authorization?
- What must be true before an external-review campaign is “ready,” and can the interface summarize that without becoming a new system of record?
- Which settings change weekly, quarterly, or almost never, and should that frequency affect Overview prominence?
- Can “reviewer” remain safe terminology without explicitly distinguishing external, discovery, and internal Final Writeup roles?
