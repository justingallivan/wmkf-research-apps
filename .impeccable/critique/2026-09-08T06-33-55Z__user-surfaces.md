## Design Specificity

Workflow surfaces are distinctly WMKF-authored: cycle-aware request work, reviewer traffic, responsible PDs, coordinator matrices, and review disclaimers. Suite entry is more generic: long emoji navigation and lifecycle-based home categories make it feel like a toolbox directory rather than a focused grant-work operating system.

## Strengths

- Neutral surfaces, restrained semantic color, thin borders, and dark primary actions closely follow the Clear Workbench system.
- Reviewer status uses text, counts, progress, and accessible labels rather than color alone.
- Cycles, PD ownership, reviewer stages, and coordinator review provide product-specific structure.

## Priority Issues

### [P1] Global navigation overwhelms the work surface

The desktop shell can wrap roughly 14 destinations into three rows before task content. Group secondary destinations into Work, Analysis, and Admin menus while retaining a compact launcher. Suggested commands: `$impeccable distill`, `$impeccable layout`.

### [P1] Final Writeups is too wide for confident comparison

The coordinator matrix requires horizontal scanning and makes row/status association difficult. Add a responsive request-card view or sticky identity column with reviewer-first filtering. Suggested command: `$impeccable adapt`.

### [P1] Status language does not consistently expose the next action

“Updated,” “Not reviewed,” “3 earlier version,” “Group review,” and “going-forward” require insider knowledge. Pair action-oriented copy with current-version/provenance details. Suggested commands: `$impeccable clarify`, `$impeccable harden`.

### [P2] Suite entry uses internal taxonomy rather than staff intent

Concepts, Phase I, Phase II, and Other Tools are lifecycle vocabulary, not task goals. Lead with Review a request, Manage reviewers, Read reports, Explore CRM data, and Run exports. Suggested command: `$impeccable shape`.

### [P2] Mobile navigation controls are not self-describing

The hamburger lacks an accessible label/expanded state and the profile control is avatar-only. Add `aria-label`, `aria-expanded`, and `aria-controls`. Suggested command: `$impeccable audit`.

### [P2] Empty/error states lack recovery direction

Generic no-work and load-failure messages should offer Clear filters, Show all requests, Try again, and state-specific explanation. Suggested command: `$impeccable harden`.

## Persona Red Flags

- Program Director/power user: navigation scanning cost, no shortcut/command launcher, custom div-button rows, and weak Word version/acknowledgement context.
- New staff member: lifecycle categories and app names assume organizational knowledge; contextual help is sparse.
- Reviewer/high-consequence contributor: Updated, Not reviewed, and Earlier version can be confused; current-version and acknowledgement consequences need stronger context.

## Minor Observations

Three-row navigation is visually tidy but functionally expensive. Edit audiences is too close to coordinator content. Footer attribution distracts on long pages. Sign-in imagery is generic. Workbench tabs are strong and should retain the dark active treatment.

## Questions

- What if the suite opened directly into “what needs my attention” instead of an app directory?
- Could a new staff member explain Updated, Not reviewed, and Earlier version without asking a colleague?
- Is the reviewer matrix the right primary representation, or should it become an optional overview?
- After acknowledgement, should the user feel certainty or simply completion?
