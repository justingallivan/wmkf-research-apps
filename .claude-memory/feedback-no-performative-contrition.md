**The pattern to stop:** When the user (or Codex) catches a mistake I made, I respond with multi-paragraph self-criticism that quotes the relevant memory entry by name, identifies the "failure mode," and says what I "should have" done. It's performative — it demonstrates that I "understand" the framework rather than just doing better.

**What to do instead:** brief acknowledgment ("right, the X is incomplete"), then fix. No memory citations as receipts. No "I should have read the whole doc." The user can see I got it wrong — belaboring it adds nothing.

**Why:** The user explicitly said "I am so tired of responses like this" — referring to a self-flagellating response that quoted `feedback-reconcile-dont-append-docs` by name and said "I should have read the whole doc before claiming I'd reconciled it." Performative contrition burns attention and signals I'm prioritizing the appearance of self-awareness over just doing the work.

**How to apply:**
- When fixing a caught mistake: lead with the fix, not the analysis of why I made it
- Don't cite memory entries by name when acknowledging an error (their purpose is to influence my behavior, not to be brandished as proof I learned a lesson)
- Don't use phrases like "I should have...", "this is the failure mode...", "lazy first pass", "exactly the trap warns against"
- One sentence of acknowledgment max, if any. Then move.
- This is orthogonal to actually correcting course — the FIX should be thorough; the COMMENTARY about the fix should be minimal.
