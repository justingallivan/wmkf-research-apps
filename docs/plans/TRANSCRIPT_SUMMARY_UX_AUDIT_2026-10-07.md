## 4. Bug A: failed session load exposes an editable form

**Confirmed UI defect; initial-load data overwrite not reproduced.**

[VERIFIED via `shared/components/meeting-tracker/SessionEditor.js:335`, `shared/components/meeting-tracker/SessionEditor.js:366`] Initial state is `session=null` and `EMPTY_FORM`. The effect awaits recipients/session list/cycle dashboard together and throws for any failed envelope **before** `loadDetail(sessionId)`. A bad cycle therefore prevents even a valid session detail from loading. `finally` turns loading off.

[VERIFIED via `lib/services/workbench/dashboard-service.js:271`, `pages/api/meeting-tracker/dashboard.js:51`] `cycleCodeToOdataFilter` rejects an invalid cycle with `ServiceHttpError` 400; the route sends that error. [VERIFIED via `shared/components/meeting-tracker/SessionEditor.js:539`, `shared/components/meeting-tracker/SessionEditor.js:576`] Rendering chooses summary only when `!isNew && session && !editing`; its `else` is the form. The error banner is not a failure-state gate. Save is enabled when not busy, and proposal-order edit is offered even without a loaded session.

**Isolated reproduction, 2026-10-07:** [VERIFIED via temporary Jest DOM probe against the real component; 1/1 passed] Used existing test fixture session id `11111111-1111-4111-8111-111111111111`, query `cycleCode=nope`, mocked only network/navigation/layout, and returned the real 400 error shape for dashboard.
