# Personal email defaults — suite-wide send inventory

## Scope and counting

The owner contract is shared Admin default → sender's explicitly saved default → edits for one send → editable preview; sending never saves the one-off edits. [VERIFIED via `docs/plans/PERSONAL_EMAIL_DEFAULTS_TODO_2026-09-20.md:19` and `docs/plans/PERSONAL_EMAIL_DEFAULTS_TODO_2026-09-20.md:30`.] This is a source inventory, not a claim that a Production configuration value was read. No mail, Dataverse, or other external service was accessed.

**Denominators.** A source search found **17 transport send expressions** in domain services: ten `DynamicsService.createAndSendEmail` calls, one `emailActivityAdapter.send` call, and six `dependencies.sendEmail` calls. This excludes the common transport implementation, adapter forwarder, and draft-only activity creation. They map to **56 distinct email cases** below: 22 workflow/diagnostic cases and 34 conditionally emailed operational notification types. Of the 56, **4 meet**, **9 partly meet**, **3 miss**, and **40 are not applicable** because a system job or event has no human sender. [VERIFIED via `lib/services/dynamics/email.js:217`, `lib/dataverse/adapters/email-activity.js:27`, `lib/services/review-manager/send-emails-service.js:917`, `lib/services/site-visit-materials/collection-service.js:140`, `lib/services/site-visit-materials/collection-service.js:539`, `lib/services/site-visit-materials/collection-service.js:684`, `lib/services/scheduled-email-service.js:295`, `lib/services/scheduled-email-service.js:451`, and the send-site source scan recorded below.] No Graph `sendMail`, SMTP, Nodemailer, Resend, Postmark, or Mailgun call was found in `pages/`, `lib/`, or `shared/` (`rg -n 'sendMail|/sendMail|nodemailer|smtpTransport|resend\.emails|postmark|mailgun' pages lib shared`). The September 15 feedback audit and August 26 dated transport inventory were seed lists, not substitutes for this source scan. [VERIFIED via `docs/EMAIL_SEND_FEEDBACK_AUDIT_2026-09-15.md:42` and `docs/OUTBOUND_EMAIL_INVENTORY_2026-08-26.md:28`.]

**Reading the tables.** `Admin` means `/admin` → Workflow email defaults, backed by `wmkf_appsystemsettings`; `fixed` means source copy, with no Admin template key. `Own prefs` means `wmkf_appuserpreferences` for the authenticated profile. `Preview yes` means the sender can inspect and edit the message before dispatch, even if a later immutable confirmation snapshot is read-only. `Partial` means some but not all of the owner's personal-default/preview contract exists. Compatibility-only reviewer actions remain in the route but have no current panel action. ## Operational notification emails

`NotificationService.notify` emails only when an alert was created, email is configured, and severity is `error`/`critical` or the caller sets `emailAdmins:true`; `info`/`warning` alerts without that flag remain dashboard alerts, not email cases. The subject/body are generated by the service, and recipients come from the configured category and explicit-recipient union. Thus **each row below** has fixed shared copy, no personal default, no editable preview, server-owned severity/recipient/event facts, and **not applicable** gap because it is an event notification with no human email composer. The row's type is the distinct email identifier; multiple branches of the same type are one case.
