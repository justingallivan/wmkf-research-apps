## Issue 1 — due-date extension missing from Last Action

- Screenshot: Reviewer Follow-up Request `1003046`; Liang Huang showed an extended due date of Sep 13, 2026, while Last Action remained the Sep 6 reminder.
- Root cause: `wmkf_reviewduedateoverride` stored only the new DateOnly deadline; the extension writer emitted no event timestamp.
- Fix: add `wmkf_reviewduedateextensiongrantedat`, write/clear it atomically with the override, project it through reviewer reads, and render a dated “Review due date extended” history event.

## Issue 2 — Request Workbench cycle dropdown has irregular gaps/order

- Screenshot: Request Workbench → Request list → Cycle dropdown showed scattered fiscal-year labels (December 2026, June 2020, December 2017, etc.) instead of a recent-first timeline.
- Root causes: the original service grouped and filtered on sparse legacy `akoya_fiscalyear`. The first meeting-date correction (`ffeafc47`) remained on `codex/reviewer-ui-surfacing`, so the compact-controls review branch did not include it. After that commit was cherry-picked as `9cab8c3e`, signed-in local review exposed a second defect: `buildHeaders` requested 100 aggregate rows and the adapter returned that incomplete page as successful options.
- Current fix on `codex/compact-controls`: aggregate `wmkf_meetingdate` in UTC for the two canonical Research program IDs, sort by full year/month descending, and offer June/December meetings only. The dropdown omits off-cycle and no-date groups. Request up to 5,000 month groups explicitly; reject continuation metadata, a full page, or malformed responses. Table/field restrictions (including `akoya_programid`), target interlock, and shared timeout remain enforced. Existing filter error/retry UI handles aggregate failures.
- Research scope: `shared/config/researchPrograms.js` owns the existing Medical Research and Science and Engineering Research GUIDs. `granteeResearchPrograms.js` re-exports the same set, preserving Awardees' separate Active-status and PI requirements. Request discovery preserves active/historical statuses; it excludes Directors' Directed, Staff Directed, reviewer honoraria, and unknown program IDs.
- Search options, filter-only and exact-number queries, PI joins, and dashboard visibility use the canonical `_akoya_programid_value`. Numeric Request Locator searches now use the scoped search endpoint before navigating, rather than the unrestricted request-detail resolver. The versioned session cache discards previous broad-program results and off-cycle selections on reload.
- Text-search contract: a sandbox probe found that Search filtering on the program lookup silently returned zero for a known matching Research record. Fetch bounded ranked Search candidates, then apply Research/cycle/status during canonical hydration via `findByIds`' optional filter. Its ID OR group and caller scope are parenthesized independently. Canonical hydrated program IDs are checked again before projection. Totals exclude filtered-out indexed candidates; the index ceiling still triggers the limited-results warning. A broad term can exhaust the 100-candidate index window before all Research matches are found; users must narrow it. Status/cycle filtering on the PI query remains server-side.
- Meeting-date result labels remain accurate for historical discovery: off-cycle/no-date Research records can still be found by text, number, or status without being offered as cycle choices. Explicit legacy API cycle filters retain the earlier date-range/no-date/escaped-fiscal-year behavior. No source dates or programs are rewritten.
- Sibling surfaces: the shared dashboard service also narrows Reviewer follow-up's cycles and request feed. Its merge is anchored to dashboard requests, so broader reviewer rows cannot reintroduce excluded programs. Other `findByIds` callers (reviewer authorization and initial-assessment artifacts) supply no added filter and preserve their prior queries. Direct request-detail resolution and Final writeups are separate discovery surfaces.
