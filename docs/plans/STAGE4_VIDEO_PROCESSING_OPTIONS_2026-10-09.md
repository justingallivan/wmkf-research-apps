### What the cheaper discussion cut could save

**[ASSUMED]** Full re-encode baseline: `T = 60/r + 25/r + H`, with `H = 10–25 min`. Mixed method: `T = 60/r + C + H`, where `C` is measured discussion demux/copy/remux time and `H` must be remeasured for that method. It avoids up to `25/r = 8⅓–50 min` of encoding, before subtracting `C`; at the fully busy Sandbox rate, that is at most about **$0.047–$0.284 per pair ($2.84–$17.04/year)**. This is possible savings, not a quote. Both files still require full decoding/verification and upload; their combined bytes determine egress. If the discussion begins `d` minutes early, its billed duration and storage rise by `d`; add that overlap to managed-provider minute formulas. No-overlap durations above are an arithmetic baseline, not an instruction to sacrifice discussion content.

## Sandbox persistence and cleanup contract — proposed, not exercised

**[VERIFIED via S3/S29]** Persistence defaults on. Create each attempt with `Sandbox.create({ persistent: false })` (CLI equivalent: `sandbox create --non-persistent`). This disables automatic stop snapshots, not manual snapshots. `snapshotExpiration: 0` means **never expire**; keeping one snapshot still retains media. Deleting a sandbox leaves snapshots behind.

**[ASSUMED — required implementation and benchmark checks]**

1. Use a fresh unique attempt name and a pinned media-free image; do not reuse a named sandbox through `getOrCreate`. Set `persistent: false` before downloading bytes, no drive mounts, no exposed ports, a bounded timeout and approved region. Assert returned persistence is false and mounts are empty; abort before download otherwise. No calls to snapshot/fork, no media caches or image builds, and no content or signed URLs in logs. These are application controls, not a claimed provider-wide prohibition on administrators taking snapshots.
2. Record project, sandbox name and session IDs in the attempt ledger outside the VM before media transfer. The supervisor owns cleanup on success, error, cancellation and stale-revision rejection. Delete exact scratch paths when reachable; in `finally`, stop the sandbox. A separate reaper handles supervisor death, timeout and ambiguous creation outcomes. Do not rely solely on `finally` or on deleting individual files as proof of disk erasure.
3. **[VERIFIED API mechanisms via S29]** Inspect stop's optional snapshot result; enumerate all pages with `sandbox.listSnapshots()` before deletion and `Snapshot.list({ name, projectId })` independently afterward. Correlate `sourceSessionId` with the ledger. Any snapshot is a retention incident: delete each exact owned snapshot with `snapshot.delete()`, then verify absence/deleted state. Delete the sandbox with `sandbox.delete()`; independently query/list to confirm its absence. Its old SDK object becomes inert, so an error from that object is not deletion evidence. Do not run a command to “test” a stopped sandbox, since commands can resume it.
4. Require successful authenticated, fully paginated reads. Permission errors, request failures, a merely stopped VM or an unexamined first page cannot count as clean. Poll boundedly for terminal state; retain a pending cleanup incident and retry if verification is inconclusive. Recheck from the independent reaper to catch delayed outcomes. The content-free receipt records configuration, stop/delete results, snapshot IDs/counts, verification timestamps and errors. Benchmark all failure paths with synthetic files before real recordings.
5. Treat these receipts as evidence that no media-bearing Sandbox/session/snapshot remains accessible through the tested provider APIs. They do **not** prove physical erasure, backup purge or provider log retention. Confirm contractual retention separately. Intended SharePoint outputs remain; their retention and any failed uploads require a separate exact-item cleanup policy. A cleanup failure must remain visible and prevent declaring the attempt fully successful.

## Cutting technique and what “accurate” must mean

**[ASSUMED — proposed acceptance contract]** Let `B` be the staff-reviewed boundary on the transcript audio timeline. Establish a mapping to the MP4 presentation clock from the actual matched M4A and MP4. Derive a conservative safe endpoint `E`, no later than the earliest plausible discussion onset. If mapping uncertainty cannot be bounded, do not manufacture a margin: block and ask staff to review the MP4 boundary. A constant offset is allowed only after multiple anchors support it; recording pauses may require piecewise mapping or rejection. Similar file durations do not establish any of these facts.

**[VERIFIED via owner decision]** Both outputs share logical boundary `B`. **[ASSUMED — proposed mapping]** Record its mapped MP4 time, presentation safe end `E`, and actual discussion start `G` separately. Choose `G <= E <= mapped B` when a conservative earlier endpoint is needed: intentional overlap preserves discussion and any presentation material omitted for safety. Never silently describe the actual two timestamps as identical. The staff video may start at an earlier independently decodable GOP/random-access point, provided its audio preserves the discussion onset and A/V synchronization. Open-GOP dependencies or broken start playback trigger re-encoding of that output. A naive `-ss`/copy command is not yet a validated recipe.

**[ASSUMED] Discussion acceptance differs:** complete intended discussion through source end, no missing onset, complete decode, valid stream allowlist, correct timestamps/A/V offsets and staff-only authorization in both listing and direct-open paths. Presentation frames/audio at its beginning are permitted. Discussion watermark is expected there; the presentation no-discussion detector must not be applied to it. A discussion-only failure can be retried without discarding a valid presentation; shared source/mapping uncertainty blocks both.

**[ASSUMED] Two presentation obligations must pass:** (1) no selected source content comes from after the approved boundary, and (2) no output stream plays past the approved endpoint. Duration alone proves neither. AAC encoder delay/padding, MP4 edit lists, retained packets and alternate tracks need explicit checks. A final AAC packet may contain padding; accept only proven silence/padding, otherwise trim earlier/re-encode or block. Original lossy audio can smear energy around a transition; a synthetic exact timestamp does not establish semantic privacy for real speech. Review a quiet endpoint before discussion, with measured alignment uncertainty and codec behavior accounted for. If there is no safe gap, require a more conservative reviewed cut or block.

**[ASSUMED] Minimal presentation output contract:** one H.264 video stream and one AAC audio stream (or an explicitly reviewed silent-video case), no unexpected streams, no embedded full-source payload, no recoverable hidden discussion tail in the presentation, and normal downloadable MP4 playback. No copied full-meeting captions, filenames containing private discussion, or thumbnails from the full source. An export that is only safe in one player fails.

### Steps and measurements

1. Freeze source byte hashes, exact source identities, transcript revision/boundary, FFmpeg/ffprobe version and container digest. Record codec/profile, pixel format, resolution, frame/time bases, start times, edit lists, GOP positions, packet PTS/DTS/durations, audio sample rate/channels and encoder priming/skip metadata. Inspect all streams, not only stream 0.
2. Decode M4A and MP4 audio into the same sample format for alignment. Match at least three distinct nonsilent anchors (early, near boundary, late) and test the offset between anchors. Silence/repetitive tones are ambiguous. For synthetic files compare against exact ground truth; for real files use waveform/correlation plus staff listening near the proposed boundary. Unexplained drift/pause means mapping failure, not “close enough.”
3. Run full re-encode of both outputs first, with stream-specific mapped cutoffs on a common clock; then compare an earlier-start discussion copy. Apply the privacy detector to presentation only and completeness/playback checks to discussion. Run naive stream-copy as a **negative-control candidate**, not an accepted method. Smart cut is optional only after the simple path passes. Capture resource peaks, free disk, CPU time, total time, throughput, encoded size, transfer retries and cost estimate. Do not log signed URLs or audio/text content.
4. Independently decode both entire outputs and enumerate every frame/audio interval. Map output back to retained source provenance. Inspect final video frames and all audio channels around the boundary. In the synthetic presentation, detect the post-boundary visual/audio watermark automatically against the reference; include a deliberately leaky remux and a bad-offset output to prove the detector rejects them.
5. Inspect each whole container, including packets hidden by edit lists, alternate tracks and trailing/unreferenced media. Test an edit-list-ignoring decode/remux. Packet DTS may be negative from reordering and is not alone a leak; inspect presentation intervals and actual decoded payload. Conversely, a short `format.duration` is not a pass. Verify in a second playback path (e.g. browser and VLC) for AAC priming/padding differences.
6. For the cloud finalist, run the long case three times sequentially, then simulate worker termination, expired Graph session and stale boundary revision. ### Pass/fail criteria

**[ASSUMED — proposed hard gates]** Every required presentation test must pass before staff review is offered; any ambiguous presentation evidence blocks review and Board eligibility. Discussion has the separate completeness/playback checks below.

- **Mapping:** synthetic mapping matches ground truth within one audio sample and the expected video-frame interval. Real recordings require a reviewed safe boundary on the MP4, measured residual uncertainty and an earlier endpoint that covers it. No arbitrary one-second tolerance for private speech. Segmented/mismatched source or non-monotonic mapping is a failure until explicitly resolved.
- **Video:** no source frame at/after `E`; retained frame presentation intervals end no later than `E`. No red/private frame or hidden post-boundary frame can be recovered. A frame overlapping `E` is dropped or shortened only if its source content is demonstrably safe; default to dropping.
- **Audio:** no selected source sample interval crosses `E` on any channel. Decode final exported AAC, account for delay/padding, and prove no discussion watermark/content in audible or hidden recoverable samples. If the checker accepts either deliberately leaky control, the checker fails and its results cannot authorize publication. Real presentation cut must pass automation before it is offered for staff listening and approval.
- **Container:** expected stream allowlist only, complete successful decode, no hidden full-source tail, bounded file size, timestamps and A/V offsets consistent with the frozen transform. Output duration and per-stream terminal timestamps must both be checked.
- **Performance:** proposed target <=150 minutes for both outputs of the 500 MB case (a benchmark goal, not a forecast) at 2 vCPU/4 GiB, peak memory <80% and scratch <70% of allocated capacity, with no truncation. Resource failure must stop safely; larger inputs cannot be silently admitted on evidence from small files. Missing the timing target changes sizing/venue, never the privacy gate.
- **Durability/security:** boundary or source replacement during any await makes the result ineligible; upload success alone is not publication success. A retry cannot create a current Board link to an old output. Crash cleanup is demonstrable, no full source in logs/artifacts/snapshots, and failed cleanup remains visible.
