## Sandbox persistence and cleanup contract — proposed, not exercised

**[VERIFIED via S3/S29]** Persistence defaults on. Create each attempt with `Sandbox.create({ persistent: false })` (CLI equivalent: `sandbox create --non-persistent`). This disables automatic stop snapshots, not manual snapshots. `snapshotExpiration: 0` means **never expire**; keeping one snapshot still retains media. Deleting a sandbox leaves snapshots behind.

**[ASSUMED — required implementation and benchmark checks]**

1. Use a fresh unique attempt name and a pinned media-free image; do not reuse a named sandbox through `getOrCreate`. Set `persistent: false` before downloading bytes, no drive mounts, no exposed ports, a bounded timeout and approved region. Assert returned persistence is false and mounts are empty; abort before download otherwise. No calls to snapshot/fork, no media caches or image builds, and no content or signed URLs in logs. These are application controls, not a claimed provider-wide prohibition on administrators taking snapshots.
2. Record project, sandbox name and session IDs in the attempt ledger outside the VM before media transfer. The supervisor owns cleanup on success, error, cancellation and stale-revision rejection. Delete exact scratch paths when reachable; in `finally`, stop the sandbox. A separate reaper handles supervisor death, timeout and ambiguous creation outcomes. Do not rely solely on `finally` or on deleting individual files as proof of disk erasure.
3. **[VERIFIED API mechanisms via S29]** Inspect stop's optional snapshot result; enumerate all pages with `sandbox.listSnapshots()` before deletion and `Snapshot.list({ name, projectId })` independently afterward. Correlate `sourceSessionId` with the ledger. Any snapshot is a retention incident: delete each exact owned snapshot with `snapshot.delete()`, then verify absence/deleted state. Delete the sandbox with `sandbox.delete()`; independently query/list to confirm its absence. Its old SDK object becomes inert, so an error from that object is not deletion evidence. Do not run a command to “test” a stopped sandbox, since commands can resume it.
4. Require successful authenticated, fully paginated reads. Permission errors, request failures, a merely stopped VM or an unexamined first page cannot count as clean. Poll boundedly for terminal state; retain a pending cleanup incident and retry if verification is inconclusive. Recheck from the independent reaper to catch delayed outcomes. The content-free receipt records configuration, stop/delete results, snapshot IDs/counts, verification timestamps and errors. Benchmark all failure paths with synthetic files before real recordings.
5. Treat these receipts as evidence that no media-bearing Sandbox/session/snapshot remains accessible through the tested provider APIs. They do **not** prove physical erasure, backup purge or provider log retention. Confirm contractual retention separately. The intended SharePoint presentation remains; the full staff Recording remains until the Stage 5 deadline. Failed uploads and Stage 5 removal require separate exact-item cleanup policies. A cleanup failure must remain visible and prevent declaring the attempt fully successful.

## Cutting technique and what “accurate” must mean

**[ASSUMED — proposed acceptance contract]** Let `B` be the staff-reviewed boundary on the transcript audio timeline. Establish a mapping to the MP4 presentation clock from the actual matched M4A and MP4. Derive a conservative safe endpoint `E`, no later than the earliest plausible discussion onset. Under the owner's decision, subtract measured mapping uncertainty up to and including **2 seconds**. If uncertainty exceeds 2 seconds or cannot be bounded, block generation and route the boundary/mapping issue to staff. This is issue resolution, not approval of a failed generated video; automated output acceptance still precedes final staff approval. A constant offset is allowed only after multiple anchors support it; recording pauses may require piecewise mapping or rejection. Similar file durations do not establish any of these facts.

| Technique | Research assessment |
|---|---|
| Full re-encode of retained portion | [VERIFIED via S26/S27] FFmpeg can decode, filter video frames and trim decoded audio samples before encoding. [ASSUMED] This is the simplest candidate for auditable removal. Select only approved streams; discard captions/data/attachments/chapters and nonessential metadata. Encode from the already-trimmed frames/samples; do not merely encode full content and hide its tail with an edit list. |
| Stream copy (`-c copy`) | [VERIFIED via S26] Copies encoded packets without filtering. [ASSUMED] An end cut is not automatically “next keyframe,” but packet boundaries, B-frame dependency/reordering, open GOPs and audio packet spans prevent treating `-t B` as proof. Copying a safely earlier independently decodable prefix could work but sacrifices content and still needs payload inspection. Reject naive copy for initial Board publication. |
| Smart cut | [ASSUMED] Copy complete safe closed GOPs and encode the tail from a safe random-access point. Open-GOP dependencies may require re-encoding more than one GOP; audio should be decoded/trimmed/re-encoded throughout. Codec parameters, timestamps and join compatibility need verification. Lower CPU, substantially harder proof; defer at 60/year. |
| Separate video/audio cuts | [VERIFIED via S27] `trim` and `atrim` have distinct timestamp/sample behavior and do not reset timestamps themselves. [ASSUMED] Use a shared mapped clock, not independent `PTS-STARTPTS` on unequal stream starts. Preserve original relative offsets or intentionally pad the later stream. Whole video-frame/sample intervals must lie within the approved span; round down. Remux and verify again. `-shortest` alone is not an accuracy check. |

**[ASSUMED] Two presentation obligations must pass:** (1) no selected source content comes from after the approved boundary, and (2) no output stream plays past the approved endpoint. Duration alone proves neither. AAC encoder delay/padding, MP4 edit lists, retained packets and alternate tracks need explicit checks. A final AAC packet may contain padding; accept only proven silence/padding, otherwise trim earlier/re-encode or block. Original lossy audio can smear energy around a transition; a synthetic exact timestamp does not establish semantic privacy for real speech. Review a quiet endpoint before discussion, with measured alignment uncertainty and codec behavior accounted for. If there is no safe gap, require a more conservative reviewed cut or block.

**[ASSUMED] Minimal presentation output contract:** one H.264 video stream and one AAC audio stream (or an explicitly reviewed silent-video case), no unexpected streams, no embedded full-source payload, no recoverable hidden discussion tail in the presentation, and normal downloadable MP4 playback. No copied full-meeting captions, filenames containing private discussion, or thumbnails from the full source. An export that is only safe in one player fails.

### Pass/fail criteria

**[ASSUMED — proposed hard gates, narrowed by owner closure]** Required privacy, mapping, file-integrity and publication checks must pass before staff review is offered; ambiguity in those checks blocks review and Board eligibility. The documented small Apple tail omission is a quality limitation rather than a standalone failure of these gates. The historical universal test matrix is not the release gate; the separate workflow plan must encode this distinction.

- **Mapping:** synthetic mapping matches ground truth within one audio sample and the expected video-frame interval. Real recordings require a reviewed safe boundary on the MP4, measured residual uncertainty and an earlier endpoint that covers it. Subtract the measured uncertainty only when it is <=2 seconds; greater or unbounded uncertainty blocks for staff boundary review. This permits earlier trimming, never a 2-second disclosure tolerance. Segmented/mismatched source or non-monotonic mapping is a failure until explicitly resolved.
- **Video:** no source frame at/after `E`; retained frame presentation intervals end no later than `E`. No red/private frame or hidden post-boundary frame can be recovered. A frame overlapping `E` is dropped or shortened only if its source content is demonstrably safe; default to dropping.
- **Audio:** no selected source sample interval crosses `E` on any channel.
